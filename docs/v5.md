# v5

Shipped 2026-09-22 as the default model (`v5-rl`). This page records what changed from v4, how
it was measured, and what did not work, so the next version starts from facts rather than memory.

## What shipped

| Version | What it is |
|---|---|
| `v5` | 113M base model trained on a rebuilt corpus (below) |
| `v5-rl` (default) | `v5` after GRPO on both continuation and accompaniment |

Both are on the Hub (`nicholasbien/midigenai`, folders `v5/`, `v5-rl/`) and the serving volume.
v5 uses a 598-token vocabulary; v4 checkpoints use 590, so tokenizers are not interchangeable.

**Blind A/B, `v5-rl` vs `v5` base** (the user, sides randomised, model names hidden):

| Task | RL preferred | Base preferred | Two-sided p |
|---|---|---|---|
| Continuation | 10 | 1 | 0.01 |
| Accompaniment | 8 | 1 | 0.04 |

Same method won 19–4 on v4 (p = 0.001), so the result has now held twice.

## 1. Corpus (`corpus_v5`, built by `~/midigenai_data/build_v5.sh`)

Changes from the v4 corpus:

- **Drum-label fix.** A bare `"909"` substring match had marked ~9,900 piano files as drums (the v4
  corpus had 13,193 drum tokens in the first 3M tokens of the solo-piano Aria val shard; v5 has 0).
- **Accompaniment documents.** v4 was trained on none. v5 carries accompaniment and infill documents,
  including both-direction hand splits for solo piano.
- **Audio transcriptions.** 7,994 30-second Free Music Archive clips transcribed with MuScriptor
  (large), across 8 genres the MIDI corpus barely covers. Filtered with
  `transcript_filter --preset loose --max-seconds 20` (drop the last 10 s, where the transcriber
  drifts; noise gate for clips that transcribe to a wall of notes). 7,009 train clips, tagged
  `Source_fma`, built with 8-bar accompaniment windows because 20 s is ~10 bars. Weighted 15× in the
  training mixture.
- **Ableton removed.** The user's own projects are held out of all training and used only as
  evaluation and labelling seeds. The builder refuses any manifest that reaches into an Ableton
  export directory unless `--allow-ableton` is passed.
- **Header additions.** `Tempo_0..6` (7 tempo buckets) and `Source_fma`. Vocab 590 → 598.

Held-out sets, enforced by `build_dataset --exclude-ids ~/midigenai_data/exclude_ids_all.txt`
on every pass:

- `evals/prompts_fma/` — 200 transcriptions, 25 per genre, never trained on.
- Ableton seeds — every clip, via the path rule and the id list.

## 2. Base training

`v5_113m`: 113M (`medium`), 180k steps at effective batch 64, block 2048, lr 4e-4 WSD, mixture
`aria:0.5,fma:15`, ~24 h on one H100, zero restarts (`--resume` on). Gated by two 25M smoke pilots on
the same corpus (with and without transcriptions).

Against the shipped v4, identical held-out prompts and settings, paired:

| | v5 − v4 | t |
|---|---|---|
| Continuation coherence | −0.003 | −0.1 |
| Scale consistency | +0.026 | +1.7 |
| Accompaniment pitch-class overlap | −0.051 | −2.0 (n=41; same-model rescoring moves this by 0.056) |
| Repetition on the 200 genre prompts | **−0.071** | **−3.1** |

Read: v5 base is level with v4 on the general set, and clearly less repetitive on the genres the
transcriptions cover. The gain users hear comes from the RL step, below.

## 3. Reinforcement learning

LLM judge → reward model → GRPO, the loop that won on v4 (see `docs/LLM_JUDGE.md` and PR #46).

- **Judge.** One rubric everywhere: `fit_only` ("does this belong to the same piece"). Agreement
  with the user on held-out test pairs: 0.861 authored MIDI, 0.786 transcriptions, 0.739 the user's
  Ableton music. Rubrics that ask for taste lost agreement on every distribution.
- **Reward.** A linear probe on the frozen v5's hidden states (an early block reads better than the
  final norm), fit to judge labels on on-policy v5 pairs. Probe accuracy 0.775.
- **Run shipped.** `grpo_v5_mixed_001`: continuation and accompaniment together, prompt pool over
  held-out val, transcription and Ableton seeds, group size 8, lr 5e-6, 1000 steps (~8 h, one H100).
  Best saved checkpoint: step 950. Eval reward over base +5.46 continuation, +4.75 accompaniment; an
  unoptimised metric reward rose +0.55 SD; no loop collapse on the bar-repeat check. Mixing the two
  tasks cost continuation nothing (continuation-only run A: +6.25, same shape).
- Accompaniment pairs ban drum tokens unless drums are requested (see below).

## What did not work, or did not matter

- **Model size.** A 202M on the rebuilt v4b corpus beat the 113M by 0.019 val loss on identical
  windows and was near-even in blind labels. The model is data-limited, not capacity-limited.
- **Tempo header.** Inert. Drum accompaniment under `Tempo_1` vs `Tempo_5` for the same condition:
  126 vs 117 drum notes, identical onset spacing. Reconsider before carrying it into v6.
- **More labels for a feature-based reward.** A 10-statistic reward plateaued at 0.68 held-out
  regardless of label count, because none of its inputs see the prompt. The hidden-state probe fixed it.
- **Per-genre numbers at 25 prompts per genre.** Signs flipped between runs; only aggregates are real.

## Things learned along the way

- **Uninvited drums.** Asked for a pitched part, v4 added a drum kit on 30–45% of notes. The 202M,
  trained with accompaniment documents, did so on 3%. Serving and pair generation now ban drum tokens
  unless drums are asked for.
- **Silent failures were the main cost.** A preempted run restarted from step 0 because `--resume`
  was off (~$31). Transcription shards hit a 12 h timeout. A tokenizer builder returned the wrong
  scheme. An empty id list let 183 of 200 held-out clips back into training. Railway serves the
  default for any unknown model name. Every one of these reported success. The guards added
  (`--resume`, `--exclude-ids`, the Ableton refusal, the tokenizer/checkpoint vocab check) exist to
  turn those into errors.
